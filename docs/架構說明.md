> 定案日期：2026-08-01
> Status：**Locked** — 架構已定案。後續需求應在本 Architecture Contract 之下實作，不得重新設計平台架構。如需變更架構，須先修訂本文件並重新定版。

## 文件性質

本文件是 Architecture Contract，不是 Implementation Spec。它描述系統的整體組成、各資料夾的職責、生成器之間的分離方式、以及使用者主要操作流程。實作細節（檔案怎麼拆、資料怎麼流動、用什麼技術）由實際開發時決定，本文件不予限制。

## 產品定位

目前 FSS BN 與 FSS Overlay Image 為**批次生成器**：主要目的是透過 Excel 自動產生所有成品。手動編輯屬於例外功能，僅提供必要的微調，不以完整設計編輯器為目標。

此定位僅描述這兩個生成器，未來新增的生成器不必遵循相同模式。

## 整體結構

```
FSS/
├── index.html          ← 入口平台
├── tools.json          ← 生成器清單（名稱＋路徑）
│
├── bn/                 ← 生成器 1：FSS BN
│   ├── index.html      ← BN 控制中心 ＋ 全部 BN 預覽
│   ├── js/
│   ├── css/
│   ├── forms/
│   ├── templates/
│   └── assets/
│
└── overlay-image/      ← 生成器 2：FSS Overlay Image（同結構）
```

## 入口平台

- 生成器按鈕不寫死在 HTML，入口頁讀 `tools.json` 動態產生。
- 新增生成器時：新增一個生成器資料夾 ＋ 在 `tools.json` 加一行，不改入口頁程式。

```json
[
  { "name": "BN",            "path": "bn/" },
  { "name": "Overlay Image", "path": "overlay-image/" }
]
```

## 生成器分離原則

每個生成器是一個獨立資料夾，各自帶完整的 js / css / forms / templates / assets，彼此互不相依。

入口平台僅透過 `tools.json` 管理可用生成器，不直接依賴任何生成器的內部實作。

正常情況下，新增、修改或移除任一生成器，不需要修改其他生成器的程式碼；新增或移除生成器時，僅需同步更新 `tools.json`。

## 使用者主要流程

**匯入 Excel → 自動產生全部預覽 → 檢查 → 必要時微調 → 下載全部**

「檢查」是主要流程，微調是例外。預覽項目由 Excel 資料動態建立，不在 HTML 寫死。

- **BN**：依工單規則一次產生多個版位（目前為 17 個）。版位形式不限於同一內容的尺寸變化，可能是一般圖文、不同尺寸配置、表格式、或完全不同的版面結構。使用哪套視覺版型由工單指定。
- **Overlay Image**：依資料筆數產生 N 個項目。
- 最終輸出：圖片（PNG/JPG）。

## 各資料夾職責

| 資料夾 | 職責 |
|---|---|
| `js/` | 該生成器的程式邏輯（流程、Excel 解析、下載、暫存等）。採功能拆分，避免巨型單一檔案 |
| `css/` | 該生成器的介面樣式（生成器本身的畫面） |
| `forms/` | Excel 欄位對應 |
| `templates/` | 各類成品版型與呈現規則。實際可包含一般圖文排版、不同尺寸配置、表格結構，及該版型所需的固定樣式或資源，不限制一定有哪些檔案 |
| `assets/` | 專案固定素材 |
